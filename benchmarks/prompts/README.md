# 压测语料

`bench_serve.py` 使用的提示词素材。**独立成文件而非写在脚本里**，理由与
`experiments/configs/` 相同：实验输入必须固定且可复现，改了要能在 git 里看见。

## 文件

| 文件 | 内容 | 规模 |
|------|------|------|
| `system.txt` | 长系统提示，模拟生产环境的角色设定与回答准则 | 约 700 字符 |
| `doc-kvcache.txt` | 长文档上下文 | 8,191 字符（约 5,400 token） |
| `questions.txt` | 20 个问题，每行一个，`#` 开头为注释 | — |

## 负载结构

三者拼成 `design.md` 规定的「多轮长文档问答」负载：

```
[system.txt]  +  [doc-kvcache.txt 的前 N 字符]  +  [questions.txt 中的一个问题]
└──────────────── 共享前缀 ────────────────┘     └──── 各请求不同 ────┘
```

**可变部分必须在末尾**——前缀缓存从第一个 token 开始逐块哈希匹配，中间断开则后续
全部失效。这一约束决定了负载的构造方式，详见 `docs/notes/04-serving.md` 第 3 节。

两种模式：

- **不命中（基线）**：在最开头插入唯一标记，前缀缓存完全失效，测纯 prefill 成本
- **命中（Phase 2）**：所有请求共享同一段 system + doc，仅问题不同

两次运行的差值即前缀缓存的收益。

## 语料来源

`doc-kvcache.txt` 由本仓库的 `docs/notes/01~04` 拼接生成，去除了 markdown 结构
（标题标记、表格、代码块、链接语法），保留正文散文部分。

选择自有文档而非公开数据集的原因：

- 零依赖，无需下载，仓库自包含
- 真实的中文技术文本，而非重复填充的合成串
- 主题与被问的问题天然匹配，便于人工核对回答质量
- 内容已固定在 git 中，实验可复现

**注意**：这是一份快照。`docs/notes/` 后续更新不会自动同步到此处——这是有意为之，
否则历史实验结果将无法复现。若需刷新语料，应作为一次显式变更提交，并在实验记录中
说明基线已更换。

## 新增语料

放入本目录并在上表登记即可。建议：

- 单个文档不少于 4,000 字符，否则 KV 规模太小，测不出缓存与带宽的影响
- 问题长度尽量相近，避免输入长度差异干扰吞吐测量
- 中文文本约 0.66 token/字符，英文约 0.25 token/字符（粗略估计，实际以服务端
  返回的 `usage` 为准）
